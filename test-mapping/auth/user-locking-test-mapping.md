## Observations

- **Authorization is the best-covered dimension here.** 17 of the 38 API tests are pure auth cases, and the scoped `BookingLocksWrite` role is tested on all four surfaces it could be abused through — create Login lock (row 4), unlock Login lock (row 21), unlock-all (row 22), and its legitimate Booking uses (rows 3, 20).
- **The two "empty" contracts differ deliberately and are both pinned.** The CSR collection endpoint returns `200` with an empty array (rows 15, 47); the patient self endpoint returns `404` (row 45).
- **Legacy data compatibility is explicitly covered.** Row 58 pins that reasons are now written as strings and row 59 pins that pre-migration numeric rows still read — a pair worth keeping together if either is ever touched.
- **The propagation lambda is tested at both levels for every branch it takes**, and the three "do nothing" branches (Booking lock, history row, missing Auth0 user) each have a unit test and an integration test. The integration tests assert only "no error / no batch failures" for the skip cases, though — none asserts that auth-service was actually left untouched.
- **Three scaffold `ExampleTests`** inflate the raw count; real coverage is 77 methods.
